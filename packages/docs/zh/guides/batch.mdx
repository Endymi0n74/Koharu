**文件 → 批量翻译文件夹…** 会打开一个对话框，对扫描文件夹运行 `koharu-batch`：页面在后台翻译并以图片形式写入输出文件夹；运行显示在活动中心，Koharu 本身仍可继续使用。

<Steps>
  <Step title='选择文件夹'>
    **要翻译的文件夹** 是输入（页面图片文件夹；也可以是章节文件夹，见下文）。**输出文件夹** 接收翻译后的页面图片，命名为 `page-0000.png`、`page-0001.png`……两项均为必填。
  </Step>
  <Step title='选择目标语言'>
    默认使用当前目标语言；目录中的所有模型都能很好地处理常见语言对（参见[模型指南](/zh/models/translation)）。
  </Step>
  <Step title='选择模型'>
    **模型** 一行默认为 **自动**（在可用显存内能容纳的最强目录模型）。打开选择器可以固定某个目录模型（含量化）或托管提供商（`openai`、`deepl` 等）：检测、OCR 与修复仍在本机运行，只有翻译文本经网络发送，并使用应用提供商设置中保存的密钥进行认证。
  </Step>
  <Step title='设置两个选项'>
    - **确定性翻译（温度 0）** — 默认开启：运行结果可复现；关闭可获得更多样的措辞。
    - **重新翻译输出中已存在的页面** — 默认关闭：跳过已存在的页面，因此停止的运行可以从断点继续；打开则重新翻译这些页面。
  </Step>
  <Step title='开始'>
    对话框关闭，任务出现在活动中心。启动失败（文件夹不存在、已有运行在进行）会直接显示在对话框中。
  </Step>
</Steps>

## 模型会按你的 GPU 选择

保持 **自动** 时，运行使用 `auto` 翻译：在可用显存内能容纳的最强目录模型，并始终启用视觉，页面图像随文本一起输入。首次运行会下载模型（最多数 GB），第一个页面开始前可能需要几分钟；之后的运行会复用它。选择背后的细节（估计值、实测值、`--llm`、`--quantization`）见[批量 CLI 文档（英文）](/en/fork#batch-mode-koharu-batch)。

在对话框中选定模型会覆盖这一自动选择；选择托管提供商则完全跳过本地显存预算（`--provider`）：只有翻译文本发往服务，其余阶段仍在本机运行。

## 跟踪进度、停止与继续

活动中心把运行显示为任务：阶段、页面进度、百分比以及停止按钮。

- **停止** 会结束批处理进程；已写入输出的页面保留在磁盘上，进行中的页面不会写出。
- **再次选择相同文件夹即可继续**：输出中已存在的页面会被跳过（除非开启**重新翻译**），只处理剩余页面。
- 运行会在输出文件夹旁边写出以其命名的 Markdown 与 HTML 报告（`<输出>.md`、`<输出>.html`），汇总翻译、跳过与失败的页面。全部完成后任务结束，显存释放。

<Note>
  后台运行同一时间只能有一个。启动第二个会提示已有进程在运行；请等待当前运行结束（或先停止它）。
</Note>

## 章节文件夹（卷模式）

顶层没有图片、但包含子文件夹和/或 `.cbz` 压缩包的输入文件夹会被视为**卷**：每个子文件夹与压缩包成为一个章节，按自然顺序翻译，结果按原有结构镜像到输出文件夹。自身含有页面的文件夹不会进入其子文件夹。布局规则与压缩包输出见[批量 CLI 文档（英文）](/en/fork#batch-mode-koharu-batch)。

页面级工作流请继续阅读[页面处理](/zh/guides/processing)，手动选择翻译模型请阅读[模型指南](/zh/models/translation)。

title: 'フォルダーを一括翻訳'
description: 'プロジェクトを開かずに、フォルダー内のすべてのページ（または巻全体）を 1 回のバックグラウンド実行で翻訳します。'
icon: 'folder-tree'
---

**［ファイル → フォルダーを一括翻訳…］** を開くと、スキャン画像のフォルダーに対して `koharu-batch` が実行されます。ページはバックグラウンドで翻訳され、画像として出力フォルダーに書き出され、実行状況はアクティビティセンターに表示されます。Koharu 本体はそのまま使い続けられます。

<Steps>
  <Step title='フォルダーを選ぶ'>
    **翻訳するフォルダー** が入力です（ページ画像のフォルダー。章ごとのフォルダーも可、下記参照）。**出力フォルダー** には翻訳済みページが `page-0000.png`、`page-0001.png` … の形式で書き出されます。どちらも必須です。
  </Step>
  <Step title='翻訳先言語を選ぶ'>
    既定値は現在の翻訳先言語です。カタログのすべてのモデルは定番の言語ペアを扱えます（[モデルガイド](/ja/models/translation) 参照）。
  </Step>
  <Step title='オプションを設定する'>
    - **決定論的翻訳（温度 0）** — 既定でオン。実行結果が再現されます。文章に幅を持たせたい場合はオフにします。
    - **出力に既に存在するページを再翻訳する** — 既定でオフ。既存のページはスキップされるため、停止した実行は続きから再開できます。やり直す場合はオンにします。
  </Step>
  <Step title='開始'>
    ダイアログが閉じるとジョブがアクティビティセンターに現れます。開始時のエラー（フォルダーが存在しない、実行中のジョブがある）はダイアログ内に表示されます。
  </Step>
</Steps>

## GPU に合わせてモデルが選ばれる

実行は `auto` で翻訳します。利用可能な VRAM に収まる最強のカタログモデルを、常に画像（ビジョン）付きで使用します。初回はモデルをダウンロードするため（数ギガバイト、最初のページが始まるまで数分かかることがあります）、2 回目以降は再利用します。選択の仕組み（推定値・実測値・`--llm`・`--quantization`）は [バッチ CLI のドキュメント（英語）](/en/fork#batch-mode-koharu-batch) を参照してください。

## 進捗の確認・停止・再開

アクティビティセンターには、ステージ・ページ進捗・パーセント・停止ボタン付きのジョブとして表示されます。

- **停止** はバッチプロセスを終了します。既に書き出されたページはディスクに残り、実行中のページは書き出されません。
- **同じフォルダーで再実行すると再開されます**。出力に既存のページはスキップされ（**再翻訳** オン時を除く）、残りのページだけが処理されます。
- 実行後、出力フォルダーの隣にその名前で Markdown と HTML のレポートが書き出され（`<出力>.md`、`<出力>.html`）、翻訳・スキップ・失敗のページを集計します。全ページが完了するとジョブは終了し、GPU は解放されます。

<Note>
  バックグラウンド実行は同時に 1 つだけです。2 つ目を開始すると「別のプロセスが実行中」と報告されます。現在の実行の完了（または停止）を待ってから開始してください。
</Note>

## 章ごとのフォルダー（ボリュームモード）

トップレベルに画像がなく、サブフォルダーや `.cbz` アーカイブを含む入力フォルダーは **巻** として扱われます。サブフォルダーとアーカイブがそれぞれ 1 話となり、自然順に翻訳されて、結果は出力フォルダー下に構造ごとミラーされます。自分でページを持つフォルダーがサブフォルダーに入ることはありません。レイアウト規則とアーカイブ出力の詳細は [バッチ CLI のドキュメント（英語）](/en/fork#batch-mode-koharu-batch) を参照してください。

ページ単位のワークフローは [ページ処理](/ja/guides/processing) を、翻訳モデルの選び方は [モデルガイド](/ja/models/translation) を続けてください。

Koharu downloads the native libraries and model files needed by the features you use. You do not need a full CUDA or ROCm SDK installation to run a release.

## Device selection

Startup chooses a shared ML device from the available backends: Metal on Apple silicon, then CUDA, ROCm/HIP, Vulkan, or CPU where supported. A device is selected only when the Torch, llama.cpp, and diffusion runtimes all publish a package for it, so the operating system, driver, and model backend must all support the selected path.

<Tabs>
  <Tab title='NVIDIA'>
    CUDA 13.3 support is available on Windows and Linux. Koharu selects a CUDA device only when the
    driver reports CUDA 13.3 or newer and the GPU has compute capability 7.5 or newer, which means a
    Turing-class or newer GPU with an R610-series or newer driver. See NVIDIA's [driver and
    architecture
    matrix](https://docs.nvidia.com/datacenter/tesla/drivers/cuda-toolkit-driver-and-architecture-matrix.html)
    and [driver downloads](https://www.nvidia.com/en-us/drivers/).
  </Tab>
  <Tab title='AMD'>
    ROCm/HIP support depends on the exact GPU, operating system, and driver. Install a compatible
    [AMD driver](https://www.amd.com/en/support). Koharu resolves its required ROCm runtime packages
    automatically. Check AMD's [compatibility
    matrix](https://rocm.docs.amd.com/en/docs-10.0.0/compatibility/compatibility-matrix.html) for
    platform requirements.
  </Tab>
  <Tab title='Apple silicon'>
    Koharu uses Metal for supported local inference on Apple-silicon macOS.
  </Tab>
  <Tab title='Vulkan and CPU'>
    Vulkan provides an accelerator option on Windows and Linux for llama.cpp and diffusion models,
    such as local translation, PaddleOCR-VL, FLUX.2 Klein, and RORem. Torch has no Vulkan build, so
    detection, the other OCR models, LaMa, and AOT run on CPU on a Vulkan-only machine. If no
    complete accelerator path initializes, Koharu falls back to CPU. CPU inference requires no GPU
    SDK and is slower.
  </Tab>
</Tabs>

<Note>
  The editor canvas uses WebGPU in the embedded CEF webview. It still needs a working WebGPU adapter
  and graphics driver when ML inference runs on CPU.
</Note>

## Downloads and caches

| Data                                                      | When it is needed                       |
| --------------------------------------------------------- | --------------------------------------- |
| Torch, llama.cpp, diffusion, and backend runtime packages | When their runtime is initialized       |
| Pinned or versioned model weights                         | On first use of the selected processor  |
| Local GGUF quantizations                                  | When you choose and use that model file |

On macOS and Linux, packages live under the operating system cache directory in `koharu/packages`. On Windows, they live in the `store` directory inside Koharu's installation directory. Projects live under `Documents/Koharu`; settings live in `~/.koharu/config.toml`. See [data locations](/en/reference/data).

Downloads are staged before being published to the cache. Retry an interrupted download on the next launch or model use.

## Memory and model residency

The resource monitor in the page rail footer reports process and system memory, CPU usage, and the selected device's utilization and memory. Models load on first use and stay loaded for later stages. If a stage fails with an out-of-memory error, Koharu unloads the other stages' models and retries that stage once. Saving settings unloads models, so the next run reloads them.

Start with a moderate local quantization. Smaller files usually need less memory, with a possible quality trade-off. A model that fits on disk can still exceed device memory.

### Qwen Image 2.1 reference measurements

Measured on an NVIDIA GeForce RTX 3070 (8 GB) with the model files &mdash; about 10.4 GB shared by every mode: the Q4_K denoiser, the Q4_K_M text encoder, its vision projector, and the VAE &mdash; already in the OS file cache:

| Qwen Image 2.1                    | Text-to-image 1024&sup2; | Inpainting 1 MP | Inpainting + neighbouring page |
| --------------------------------- | ------------------------ | --------------- | ------------------------------ |
| Context load                      | 0.6 s                    | 1.1 s           | 0.6 s                          |
| Wait until the first sampling step | 9 s                      | 28 s            | 44 s                           |
| Steady sampling step              | 3.7 s                    | 9.4 s           | 17 s                           |
| Whole-card memory peak            | 7.2 GiB                  | 7.6 GiB         | 7.5 GiB                        |

Weights page into VRAM on first use, so the context load stays sub-second while the wait until the first step carries the transfer, the prompt encoding, and the first step itself; the first run after a reboot adds the 10.4 GB disk read. The whole-card peak includes 1.5&ndash;2.4 GiB of desktop and browser &mdash; Qwen itself accounts for roughly 5.8&ndash;6.2 GiB &mdash; and inpainting steps run slower because every step is conditioned on the cropped page, plus the neighbouring page when the reference is enabled.

If startup fails, check network access to the package repositories, update the driver, and retry once. Capture the full error if it repeats and follow [troubleshooting](/en/reference/troubleshooting).
